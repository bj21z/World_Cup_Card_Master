# 重要会议固定新增议题：核心玩法持续创新评审

## 议题原文
游戏核心玩法是否有必要逐步尝试调整和创新，以保持游戏新鲜感？

## 纳入方式
- 只在版本立项、Beta复盘、正式发布评审、季度/阶段总结等重要会议节点加入。
- 作为固定新增议题插入原主会议流程，不改变会议编号、召开顺序、原参会名单与其他议题。
- 非重要的日常故障会、纯技术回归会可不讨论，避免干扰紧急问题处理。

## 责任分工
- 主策划：议题召集与玩法方案提出。
- 数值策划：评估平衡、概率和长期成长影响。
- AI工程师：评估AI适配与对局多样性。
- 运营负责人：评估活动化和长期新鲜感。
- 市场负责人：提供玩家趋势、竞品和测试反馈。
- 测试经理：设计A/B测试与回归门禁。
- 技术总监：评估实现成本、兼容和存档风险。
- 商业化负责人：判断是否影响公平和商业边界。
- 法务负责人：审核内容与授权风险。
- 制作人：作最终是否试验、扩大或回滚的决定。

## 决策原则
1. 不为了新鲜感破坏1—3人动态牌阵的产品辨识度。
2. 优先采用可开关、可回滚、小范围A/B测试的增量创新。
3. 任何核心规则调整必须有玩家数据、模拟结果和回归测试支持。
4. 同一测试轮次不同时改变多个核心变量。
5. 试验失败可迅速回退，不污染正式存档和公平竞技。

## 每次会议必须输出
- 是否需要调整：否 / 观察 / 小范围试验 / 正式立项。
- 试验对象、成功指标、停止条件和回滚方案。
- 第一责任人、协同部门和下次复核节点。
